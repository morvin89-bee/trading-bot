ZONA = ZoneInfo("Asia/Jakarta")          # sudah dipakai dca_window

def lokal(ts):        return datetime.fromtimestamp(ts, ZONA)
def hari(ts):         return lokal(ts).strftime("%Y-%m-%d")
def bulan(ts):        return lokal(ts).strftime("%Y-%m")
def jam(ts):          return lokal(ts).hour

## Butir 2 — gerbang jual > kepemilikan

**Sumber pembanding: SALDO BURSA, bukan hitungan trades.**

- `main_loop.baca_konteks` → `portfolio.compute_holdings(trades, balances, prices)`.
- `balances` berasal dari `portfolio.parse_balances(account_info())` =
  `free + locked` per koin — otoritatif terhadap bursa.
- `trades` hanya dipakai untuk harga rata-rata/`basis_known`, **bukan** untuk
  kuantitas (`compute_holdings` docstring: "Kuantitas diambil dari
  `balances` (otoritatif)").
- Gerbang: `engine.on_answer` langkah 2b —
  `p.qty is None or p.qty <= 0 or p.qty > dimiliki + 1e-9` → `gate_blocked`,
  satu pesan Telegram menyebut qty dan kepemilikan, nol order, nol tulisan
  `setuju`.

**Toleransi pembulatan: absolut `1e-9` koin.** Cukup untuk menyerap galat
penjumlahan float satu holding; 1e-9 BTC ≈ Rp 0,002 pada harga Rp 2 M —
bukan kuantitas nyata. Toleransi ini **tidak** berskala per pair, jadi
koin berharga murah (mis. 1e-9 SOL) tetap di bawah nilai ekonomi terkecil.

**Presisi qty per pair: TIDAK ADA.** `executor.payload_for` meneruskan
`p.qty` sebagai float apa adanya; `indodax_transport.post_order` menaruhnya
di kunci simbol koin dan `_v1_call` meng-`urlencode`-nya. Tidak ada
pembulatan tick/lot per pair, tidak ada validasi `stepSize`. Risiko:
bursa dapat menolak qty dengan desimal berlebih (fail closed di bursa) atau
membulatkannya sendiri. **DECISION FOR ME** di bawah.

**Tes** (`tests/test_engine.py`):
`test_jual_seluruh_posisi_diizinkan` (qty == kepemilikan → order terkirim),
`test_selisih_desimal_kecil_tidak_menolak_jual` (+1e-10 lolos, +1e-6 ditolak),
`test_saldo_bursa_lebih_kecil_dari_catatan_menolak_jual` (holding 0,5 vs
usulan 1,0 → `gate_blocked`, nol order, pesan "kepemilikan").

## Butir 4 — `python -m preflight` (read-only)

Modul baru `preflight.py`, dijalankan `python -m preflight`. Mencetak
`[OK]/[GAGAL]` per pemeriksaan lalu `GO` atau `NO-GO` + alasan; exit code
0/1.

**Pemeriksaan:**

1. **Zona waktu** — `main_loop._offset_zona_lokal` harus
   `ZONA_OFFSET_DETIK` (sumber yang sama dengan penjaga `main()`).
2. **Basis data & migrasi** — dibuka `file:...?mode=ro` (berkas yang belum
   ada = gagal, tidak dibuat). Wajib ada tabel `trades`, `bot_state`,
   `proposals`; `bot_state` wajib punya 7 kolom (termasuk hasil migrasi
   `shadow_checked_day`, `telegram_offset`); `proposals` wajib punya 16
   kolom (termasuk `qty`, `reserve_after`, `window_s`, `level`, `basis`,
   `revisi`). Kolom kurang = `NO-GO` "migrasi ... belum diterapkan".
3. **Izin kunci** — `indodax_transport._env_bool("INDODAX_CAN_TRADE")` dan
   `_env_bool("INDODAX_CAN_WITHDRAW")`
   dinilai `safeguards.permissions_ok(..., switch_on=bool(v1_enabled))`.
   `canWithdraw` aktif, izin tak terbaca, atau `canTrade` tidak cocok
   dengan sakelar = `NO-GO` (memakai teks alasan yang sudah ada).
4. **Jam bursa** — `GET https://indodax.com/api/server_time` (satu-satunya
   jaringan), selisih vs jam mesin harus ≤ `TOLERANSI_JAM_DETIK = 5`.
   Gagal baca = `NO-GO`.
5. **Mode** — `v1_enabled` nyala = lolos; mode bayangan = butuh
   `shadow_day >= GO_LIVE_SHADOW_DAYS` (7).
6. **Jendela DCA bulan ini** — status `none/awaiting/confirmed/missed/
   lewat`; `dca_status` di luar `STATUS_DCA` atau `dca_sent_ts` kosong =
   `NO-GO` (data rusak).

**Jaminan read-only.** `dca_window.dca_state` **tidak** dipakai karena

## DECISIONS FOR ME

1. **Presisi qty per pair (butir 2).** Belum ada pembulatan tick/lot;
   `p.qty` dikirim sebagai float mentah. Pilihan: (a) biarkan — bursa
   menolak/membulatkan sendiri (fail closed, tetapi bisa jadi penolakan
   berulang); (b) tambah tabel `stepSize` per pair dan bulatkan ke BAWAH
   sebelum gerbang; (c) bulatkan ke bawah hanya di `executor.payload_for`.
   Saya tidak memilih sendiri karena ini menyentuh uang dan butuh angka
   resmi bursa per pair.
2. **`client_order_id` > 36 karakter.** `executor.make_client_order_id`
   memotong dari UJUNG, yaitu bagian timestamp — dua order berbeda bisa
   bertabrakan bila prefix panjang. Prefix yang dipakai sekarang pendek
   (id proposal), jadi belum terjadi; perbaikan (potong prefix, bukan
   timestamp) mengubah id dan sebaiknya diputuskan bersama rekonsiliasi.
3. **Helper waktu bersama.** Lihat usulan `waktu_lokal.py` di butir 1.
   Peralihan aman hanya karena mesin kini dijamin WIB oleh penjaga start.
4. **Batas `shadow_day` di preflight.** Saya menetapkan mode bayangan
   `< 7` hari = `NO-GO`. Bila Anda ingin preflight juga berguna sebagai
   "boleh start bayangan?", batas itu perlu dipisah (mis. `--boleh-bayangan`).
